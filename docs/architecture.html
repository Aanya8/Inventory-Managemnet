Data Flow — Filter Change to Render

1
User changes a filter dropdown
FilterBar.vue updates a ref in useFilters.js composable (e.g. selectedLocation.value = 'Tokyo'). The composable is a singleton — all views share the same state.
2
View component reacts
The active view (e.g. Inventory.vue) watches the filter composable. When a change is detected, it calls getCurrentFilters() and triggers a data reload.
3
API call dispatched via api.js
Centralized api.js builds a URLSearchParams object, skipping 'all' values. Example: GET /api/orders?warehouse=Tokyo&status=delivered&month=2025-09
4
Backend filters in-memory data
main.py receives query params as Optional[str]. apply_filters() chains warehouse → category → status filters. filter_by_month() handles both YYYY-MM and Q#-YYYY quarter formats.
5
Pydantic validates & serializes response
FastAPI validates the filtered list against the Pydantic model (e.g. List[Order]) and returns a JSON array.
6
Vue re-renders with new data
Axios resolves the promise. The view updates its reactive items ref. Computed properties (e.g. aggregates, chart data) recalculate automatically. Template re-renders.

Filter System

Time Period
?month=YYYY-MM
All months in 2025, Q1–Q4 quarters
Applies to: DashboardOrdersReports
Warehouse
?warehouse=San Francisco
San Francisco, London, Tokyo
Applies to: DashboardOrdersInventory
Category
?category=sensors
Circuit Boards, Sensors, Actuators, Controllers, Power Supplies
Applies to: DashboardOrdersInventory
Order Status
?status=delivered
Delivered, Shipped, Processing, Backordered
Applies to: DashboardOrders
